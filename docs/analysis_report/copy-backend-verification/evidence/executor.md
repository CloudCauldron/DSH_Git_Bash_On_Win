# Executor cutover and independent reviews

All three verification rounds below ran on Windows 11 build 26200 in native Git Bash with Windows Node 26.12.1 and DSH 0.2.2-rc.5. At cutover of the production executor, publisher, and settings page to the ordinary-copy cache, typecheck, lint, and the clean release build passed alongside the Windows suite (163/163), the browser suite (1/1), the `mingw64` executor matrix (8/8), and the `mingw64` PE/native checks (49/49). The browser-only build left the DLL intact, a missing-DLL fixture failed before starting Chrome, and all four raw locale files matched the [locale baseline](baseline.md#preserved-locale-bytes).

## Executor and publication audit

The first audit reproduced delayed timeout delivery during native workspace lookup, duplicate recording of a single close failure, and loss of an explicit environment key. Cache tests also caught a growing owner marker at cold start, a missing payload masking a separate read failure, and a patched DLL exceeding the warm-admission size bound. The fixes in `de5ad38` passed the Windows suite (166/166) and browser suite (1/1), with short-path tests updated to require Windows to supply a distinct leaf spelling.

A second review traced the admitted workspace into DSH's confinement service, leading the executor to hand stock DSH a private policy copy carrying the canonical workspace (tested with frozen caller policies). Explicit blank settings now fall back to default Git discovery even when the settings document is read-only, and tests verified that a worker can publish a different Git root while a parent still pins the old one, with a subsequent build collecting the released generation.

Both audit rounds passed typecheck and lint, ending with 166/166 on the Windows suite, 8/8 on the `mingw64` executor matrix, and 19/19 on packaged PowerShell, WinGet, and GDB. The rc.5 Desktop executable and `app.asar` ran the audited package in an isolated profile across all three modes with zero visible native child consoles (1,568 window samples), passing Settings rebuild, navigation, normal exit, and offline purge while matching the locale baseline and cutover DLL hash.

## Settlement, paths and build outputs

At reviewed baseline `66a2cf1`, the diff from provisioning revision `6b091b7` totaled 2,173 insertions and 8,020 deletions (net −5,847 lines), with the native source growing by 12 lines net and keeping the same import allowlist. The package retained five direct runtime dependencies and 47 lockfile-matched release-age exclusions, and a clean release build matched the tracked outputs.

Before fixes, controlled disposal tests observed two waits on one active child and duplicate diagnostics for repeated unconfirmed settlement; updated tests enforce a single active wait, a single diagnostic, and pin retention until positive settlement, while still allowing a failed pre-disposal wait to succeed on retry. A corrupted source MSYS fixture previously wrote one ordinary payload before aborting; it now writes zero and keeps the active generation selected.

With those fixes in place, typecheck, lint, the Windows suite (172/172), the `mingw64` PE/native/executor suites (89/89), and the packaged PowerShell/WinGet/GDB suite (19/19) all passed. Long and 8.3 Bash paths produced the expected namespace key on both Git layouts across read-only, bound workspace-write, and agentless workspace-write. The browser suite passed 1/1 with an unavailable compiler configured, and an isolated missing-DSH control produced the two expected bootstrap failures with zero skips.

All 29 tracked build outputs matched across clean release, development, and browser-only builds, two isolated native builds reproduced SHA-256 `0350d5533d5e887f47045ba1787db9dfaacbb9cffdbe5887feeb0e64a7ff75b7`, and the four locale files matched the baseline. Finally, packaged rc.5 Electron/ASAR Desktop ran all three modes in an isolated profile, wrote version 1 to the marker and selector, rebuilt from Settings, navigated away, exited normally, and released the cache for offline purge.
