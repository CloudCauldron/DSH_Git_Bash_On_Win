# Backend design decisions — 22 November 2026

This record governs replacement of the debugger-supervised hardlink backend with ordinary copies and an in-process compatibility DLL. The target is DSH 0.2.2-rc.5 on native Windows 11 x64, using ucrt64 or mingw64 Git layouts. Implementation starts from `33fa0a9039d193452ccab7eefc222144437f8aaa` on `be_refactor`. Phase 1 adds the qualified native artifact, PE contract and build checks. Phase 2 exercises the shallow copy layout directly. Phase 3 publishes this layout for all commands and removes the debugger, launcher and elevated setup services.

Keep the [2026-11-17 design](backend-20261117-design-decisions.md) as history and consolidate the implemented architecture here. This document records durable choices and rejected alternatives; the roadmap owns the phase-by-phase checks.

## Execution and native admission

DSH owns confinement, grants, process creation, stdio, deadlines and managed-range settlement. The plugin replaces the checked Bash command tail and finalizes PATH, GIT_EXEC_PATH, GIT_TEMPLATE_DIR and MSYS2_PATH_TYPE at the invocation-local spawn boundary. Keep `commandReceiver` private in index.ts beside command ownership; adapter.ts retains Loader/config integration. Preserve DSH's assembled environment-map ordering and runner-owned TMP/TEMP.

Retain the raw subprocess handle until positive `waitForExit()` settlement. Failed waits retain ownership; disposal uses the handle even when ShellExecution already says killed. Disposal terminates/joins only records that have a child. If DSH times out or cancels a command during workspace resolution or confinement, the caller receives DSH’s result immediately. Disposal joins the unfinished preparation, which retains its use until it settles. Each release attempt is memoized and tracked once. Pending releases are observed, while a settled failed release stays recorded without being invoked or recorded again. The accepted AppModel boundary matches stock pwsh-sandbox: a packaged root's native descendant can outlive reported settlement. No replacement supervisor or descendant sweep is added.

A command that starts cold preparation checks workspace overlap before creating the cache or writer lock. A ready command acquires its generation reference before workspace admission. Canonicalize the workspace once in the plugin for overlap admission with promisified `fs.realpath.native`, retaining absolute-path validation. DSH independently canonicalizes it through `canonicalPath()`. Compare runner workspace with the admitted canonical value and runner mode with the captured mode. The ACL runner already checks the workspace SID. The plugin validates paired SID flags and the exact temp capability used in its view name. Agentless workspace-write retains explicit `ww-u` because the runner creates its private temp after confinement returns; fabricated sessions or a custom grant manager would add grant lifetimes and machinery.

The zero-CRT shim retains five MSYS IAT hooks, exact loader-path and mapped-file identity checks, independent policy/token admission and read-only protection restoration. A matching MSYS basename with a missing, malformed, oversized or unexpected full path fails admission. Preserve selected TEMP-first/TMP-fallback validation and the default-DACL branch for MSYS children whose environment omits both variables. Native and packaged children receive no shim injection.

The section ACL adjustment applies to `cygpid.<pid>` in the view’s global MSYS object directory. Both qualified runtimes create named process sections there. They use a separate directory for Windows-session objects and abort if global directory creation fails. Matching session directories would extend the grant to unrelated objects. Imported function names use exact case, and an unreadable ACE supplies no evidence of a grant. [MSYS 3.6.10 section creation](https://github.com/git-for-windows/msys2-runtime/blob/5a1665c8/winsup/cygwin/kernel32.cc#L280-L350) · [MSYS 3.6.9 directory selection](https://github.com/git-for-windows/msys2-runtime/blob/b4195d69/winsup/cygwin/mm/shared.cc#L29-L91)

A native caller can spell the complete Bash entry with NTFS short names. Compare the loader's original sibling paths first. When the admitted view contains a tilde, expand its spelling with the bounded Windows long-name lookup before deriving the MSYS namespace and parsing the policy leaf. The on-disk and mapped MSYS identities must still match, and the expanded leaf must pass the same policy and token checks. The policy grammar and patch ABI are unchanged. The bundled DLL digest invalidates earlier copies.

Probe `TokenLogonSid` against TokenGroups on actual DSH tokens before replacing the full-group scan. Check count, returned size, SID bounds and the necessary logon-ID attributes rather than the entire observed attribute word. Keep restricting-SID membership, bounded storage and SID lifetimes through copying; add no heap allocation or fallback under loader lock.

Hook 5 redirects only direct source/runtime usr/bin children into the view, using the mandatory etc junction to resolve source. Keep native bin/bash.exe distinct. Unrelated, rewrite and error outcomes remain separate; input, long-path-expansion and output overflow return `ERROR_FILENAME_EXCED_RANGE`, and failed rewrites never retry installed source. Short-name expansion retains the caller’s extended-length prefix for the Win32 lookup. Root comparison strips the prefix from the result, and unrelated launches receive the caller’s original path. Root resolution propagates the error reported by a failed Win32 open or close. Use `InitOnceExecuteOnce` outside attach to publish complete roots or a terminal error. Complete the once callback for either recorded result and let the wrapper report errors; a FALSE callback would permit retries. [Microsoft once-initialization contract](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-initonceexecuteonce).

## Cache construction and lifetime

Flat ordinary copies remove UAC, source hardlinks and source/cache volume coupling. Preserve every executable alias: the measured 355 source files total 92,906,374 bytes, and the private MSYS patch plus shim bring a generation to about 88.62 MiB. Other Git resources remain junction-backed. All DSH instances must close throughout same-root Git upgrades; there is no live-upgrade coordinator or whole-Git snapshot.

Require ordinary source etc and bin directories plus native bin/bash.exe for either selected Bash entry, including usr/bin/bash.exe. Discovery, provisioning, warm admission and fixtures use this one contract. The builder rechecks the mandatory targets before creating the private layout and uses those admitted directories for the junctions. The etc junction supplies Hook 5's source witness; bin preserves native wrappers. Junction admission reads the stored target, checks its directory components without following reparses, and compares the target’s NTFS volume and file ID. This distinguishes ordinary directories whose names JavaScript lowercases identically and rejects intermediate junctions. Supporting stripped trees through optional-bin branches would add a layout variant without a target use case. Preserve required Perl/lib/libexec resources and exclude source tmp/dev.

Storage remains under the owned DSH-home cache, with its delete-on-close sibling writer lock. Ownership binds the root path and file identity. Refuse unknown, markerless and legacy roots; the fresh-install contract uses the old uninstaller, so migration and legacy link-count restoration do not ship. Short generation/view paths and the 260-byte UTF-8 guard reject over-budget homes before copying. Source/cache/workspace overlap is rejected before grants or mutation.

Use native no-follow source reads with short-lived FILE_SHARE_READ handles. Check same-handle BigInt size before allocation: 64 MiB for payloads and smaller metadata limits. Reuse each handle's memoized kind/identity/size; later freshness samples open new handles. Check short reads, EOF/growth and conversion bounds. A shared Node `wx` writer creates independent files with inherited cache permissions, avoiding source ReadOnly/ACL copying. Aggregate write/close/rollback errors and never remove a pre-existing collision. Ordinary unpublished-payload close errors reject the attempt; native hold/lock/claim close failures remain fatal.

Pin sourceBin and destBin once for the flat pass. Standalone metadata writes use a self-pinning wrapper around the same writer. Close each file handle before yielding, and all directory holds on exit. Keep per-file cancellation points until measurements justify batching. Reject a separate NT destination writer: hostile same-user parent conversion is outside the cooperating-host cache model, and other creation/publication operations also use paths.

Source freshness combines Git and MSYS file stamps with a raw hash of optional etc/package-versions.txt, bounded to 256 KiB. Recheck the entire key before publication. This catches normal packaged upgrades without spawning Git or restoring six-anchor/tree inventories; Save and rebuild repairs custom edits that preserve the key. Each `prepareRuntime()` reads and hashes the bundled shim into local variables used by that attempt. Nothing is cached across preparations or re-read on ready commands, so a later preparation naturally sees updated bundled bytes.

On a matching source key, warm admission checks both shells and both private DLLs before classifying the payload as stale. A missing shell or digest mismatch cannot hide an access, structural or close failure in another required file. Digest mismatches or missing ordinary Bash/sh/DLL payloads trigger rebuilding, including a changed bundled shim with unchanged patch ABI. Unexpected reparses, redirected/dangling junctions, wrong types and access/read/close failures remain errors. Failed automatic rebuilding never serves stale disk copies. Validate new files/junctions as they are created and hash patched bytes before writing, avoiding a second complete destination scan immediately before publication.

Publish current.json with DSH atomic write while holding the writer lock and a generation pin. Publication remains authoritative after rename succeeds, even if cancellation or later cleanup fails. Readers pin then reread the selector; collectors take an exclusive claim before traversal. Pre-create v/ with the generation, reuse views synchronously, and validate a reused junction against its pinned runtime.

Keep collection at build and offline-purge boundaries. A build scans unselected orphans once, then attempts only the superseded generation after publication under the same lock. Pin release cleans owned views and closes its hold; it does not read selectors, acquire writer locks or traverse payload. This removes final-reference GC and its one-shot lock helper. A separate collector after rebuild was also rejected: active commands or peers may still pin the old generation, so it adds another cleanup path without guaranteeing reclamation. Superseded copies may remain until a later build or purge; there is no fixed one-extra-generation bound, quota or background collector.

Keep work and cleanup in separate promise sets. Manual rebuild may publish B while commands use A; new preparation drains cleanup, not those active command lifetimes. Disposal joins preparation and owned children, closes instance handles and attempts owned-view cleanup. Offline purge validates ownership, claims generations and unlinks reparses without following targets. It removes the owner marker after the payload and immediately before deleting the empty root. Process termination between those final operations can leave an empty, markerless directory, which subsequent admission refuses. Blocked or interrupted purge fails explicitly. Installed Git/DSH contents, ACLs, global environment and registry remain untouched.

## Build, packaging and dependencies

Share a bounded PE header/section/import reader and fixed MSYS patcher. Preserve ordinal imports and repeated descriptors, and expose DLL characteristics and export-directory fields from that parse. Build-only code interprets shim exports and validates mitigations/imports. The patch retains existing section positions and supported symbol/debug tails, bounds its new section header by both raw data and SizeOfHeaders, updates initialized-data size and checksum, and keeps the IAT span read-only. Source admission is structural rather than a source-hash whitelist; tested versions are recorded separately.

The patcher accepts unbound MSYS imports. Both qualified Git images have zero descriptor timestamps and forwarder chains. Rejecting bound descriptors preserves the original IAT bytes and avoids implementing rebinding. The reader requires an eight-byte-aligned NT header after the DOS header, nonempty mapped sections and nonempty names. These checks keep the checksum field aligned, give each section a distinct address and reject invalid imports before publication. [Microsoft PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)

Canonical native source lives outside disposable lib/. One fixed build script uses the reviewed zero-CRT flags and `/Brepro`, private system-temp scratch and checked cleanup. Every build enforces PE invariants and the named-function allowlist. Keep allowed membership rather than exact import equality: removed imports need no manifest edit, additions need review. A DLL-only allowlist or API deny-list misses unsafe functions; a release hash cannot validate a new development candidate.

Development builds report their actual tool versions/hash and remain testable before hash approval. Release builds and prepack require recorded tools and the approved hash. Compare two isolated builds before updating pins, then qualify the final DLL and tarball. Clean lib before building to remove obsolete outputs, package the DLL without native source/build scripts, and require no install-time compiler. Two-tree comparison belongs in release qualification rather than recursive prepack checks. The build verifier reads DLL names from the manifest’s own entries. The isolated-build test supplies invalid ambient compiler options and search paths so that a build depending on them fails.

Keep five direct runtime dependencies: `@deepseek-ai/schemastery`, `@deepseek-ai/dsh-atomic-write`, `@deepseek-ai/dsh-error`, `@deepseek-ai/dsh-win32-process` and `koffi`. Host Cordis/ACL peer identities remain shared, and SID-helper imports stay outside the standalone purge graph. Resolve the bundled DLL with `../../lib/dsh-msys-compat.dll` relative to runtime-cache, valid for source tests and packaged output. Remove obsolete filesystem exports with their debugger/setup callers. Add the UI-primitives development pin and release-age exclusion; prune other exclusions only when the retained dependency graph no longer needs them.

## UI and verification boundaries

Use native SettingsForm, SettingsValueField, Modal and Toast with page-local state and one rebuild endpoint. Preserve Save and rebuild, revision conflicts, blank-path reset, unchanged-path rebuilding with read-only settings and the saved-path/rebuild-failure distinction. Rich errors use Modal children. Guard async updates on unmount and handle rejections; navigation leaves accepted backend work running, and a later click can show the existing busy response. Delete global overlay, feedback/progress transport and custom styling; keep src/locale/ unchanged.

Use a small independently encoded PE32+ MSYS fixture for cache and PE tests instead of their current text payload or a full installed DLL per test. Include the five required named imports, valid terminated descriptors/thunks, header room and read-only IAT data; pass it through the real patcher without production exceptions. Malformed fixture cases assert the diagnostic for the intended invariant. The native test sets invalid UTF-16 through Win32 because Node replaces the surrogate before the OS receives it. Keep executable/native qualification on owned real Git in both layouts. Synthetic fixture size is an implementation detail, not a 1.5 KiB target.

Share observers in fixtures.ts. Keep exhaustive PEB/token/ACL negative controls and 100-fork stress in native-compat.test.ts; real-executor tests cover argv/env/policy/lifetime plus representative image/view/fork and four-caller IPC checks. Reused-view tests allow junction validation while forbidding selector/freshness/DLL rereads. UI tests assert native form usability and rich dialog content instead of custom geometry or paragraph tags.

Keep browser testing in test:release. Preflight DSH, Git and the Chrome executable before builds or fixture setup, using CHROME_PATH or the existing Program Files default through a shared small resolver. Missing Chrome is an early error, not a skipped browser suite. UI-only testing preserves the DLL from a prior full build and checks its existence; PE verification stays in build/native/release checks. Native edits require a full build.

Discover platform prerequisites in Phase 0, probe TokenLogonSid and real mingw64 startup in Phase 1, measure cold copying under active Defender in Phase 2, and verify first-command deadlines and actual Electron/ASAR after Phase 3. Shared preparation may outlive a timed-out caller, but that command must never spawn later. Optional aliases/gdb remain explicit host qualification, with WinGet logging opt-in and missing coverage marked UNVERIFIED. Preserve normal endpoint protection; do not change settings or recommend exclusions.

Both READMEs explain practical differences from native Linux Bash, accepted command limits, retained-generation storage, all-instances-closed Git upgrades and automatic next-use rebuilding. Manual rebuild is repair; complete removal clears only the plugin override, closes sharing hosts, purges once and uses official package operations while preserving shared Shell settings.
