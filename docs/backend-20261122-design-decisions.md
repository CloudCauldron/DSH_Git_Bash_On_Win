# Backend design decisions — 22 November 2026

The plugin runs Git Bash under DSH 0.2.2-rc.5 on native Windows x64 from a shallow tree of ordinary executable copies. A private MSYS runtime loads an in-process compatibility DLL. The primary qualification host ran Windows 11 with both ucrt64 and mingw64 Git. A separate Windows 10 host exercised a cross-volume deployment. The shipping revision before the change was `33fa0a9039d193452ccab7eefc222144437f8aaa`.

The [Windows experiments](analysis_report/refactor-design-validation/README.md) explain the loader, lifetime and storage constraints behind the change. The [November 17 design](backend-20261117-design-decisions.md) describes the superseded process-family backend.

## Execution and native admission

DSH owns confinement, grants, process creation, stdio, deadlines and managed-range settlement. The plugin replaces the checked Bash command tail and finalizes PATH, GIT_EXEC_PATH, GIT_TEMPLATE_DIR and MSYS2_PATH_TYPE at the invocation-local spawn boundary. The private `commandReceiver` in `src/index.ts` owns command completion. `src/adapter.ts` handles Loader and settings integration. The executor preserves DSH’s environment-map ordering and the runner’s `TMP` and `TEMP`.

The executor holds the raw subprocess handle and runtime lease until `waitForExit()` confirms settlement. A failed wait leaves the command owned. During disposal the executor terminates the retained child even if `ShellExecution` already reports it killed. It shares a wait in progress, or retries if an earlier wait failed. Repeated unconfirmed results for one command yield one diagnostic. Distinct wait errors remain visible. A native descendant of a packaged root can outlive settlement, as observed with stock `pwsh-sandbox`. [Measured AppModel counterexample](analysis_report/refactor-design-validation/evidence/managed-range.md)

If a deadline or cancellation arrives during workspace resolution or confinement, DSH returns its result immediately. Preparation retains its runtime reference until it settles, and disposal joins that work. The executor tracks each release attempt once and preserves a failed result for diagnosis.

A cold command checks for workspace overlap before creating the cache or writer lock. A ready command takes its generation reference first. The plugin validates an absolute workspace path, resolves it once with `fs.realpath.native` and passes an invocation-owned policy containing that path to DSH before confinement applies grants. DSH independently calls `canonicalPath()`. The plugin checks the returned path and policy mode against the admitted values.

The ACL runner checks the workspace SID. The plugin validates paired SID flags and the exact temp capability used in its view name. Agentless workspace-write uses the explicit `ww-u` form because the runner creates its private temporary directory after confinement returns. This keeps grant lifetimes with DSH.

### Loader and token admission

The zero-CRT shim retains five MSYS IAT hooks, exact loader-path and mapped-file identity checks, independent policy/token admission and read-only protection restoration. A matching MSYS basename with a missing, malformed, oversized or unexpected full path fails admission. Admission checks `TEMP` first and falls back to `TMP`. MSYS children can lack both variables during DLL initialization, so their admission uses token and default-DACL evidence. Native and packaged children receive no shim injection. [Loader and environment observations](analysis_report/refactor-design-validation/evidence/loader-and-shim.md)

The section ACL adjustment applies to `cygpid.<pid>` in the view’s global MSYS object directory. Both qualified runtimes create named process sections there. They use a separate directory for Windows-session objects and abort if global directory creation fails. Matching session directories would extend the grant to unrelated objects. Imported function names use exact case, and an unreadable ACE supplies no evidence of a grant. [MSYS 3.6.10 section creation](https://github.com/git-for-windows/msys2-runtime/blob/5a1665c8/winsup/cygwin/kernel32.cc#L280-L350) · [MSYS 3.6.9 directory selection](https://github.com/git-for-windows/msys2-runtime/blob/b4195d69/winsup/cygwin/mm/shared.cc#L29-L91)

A native caller can spell the complete Bash entry with NTFS short names. Compare the loader's original sibling paths first. When the admitted view contains a tilde, expand its spelling with the bounded Windows long-name lookup before deriving the MSYS namespace and parsing the policy leaf. The on-disk and mapped MSYS identities must still match, and the expanded leaf must pass the same policy and token checks. The policy grammar and patch ABI are unchanged. The bundled DLL digest invalidates earlier copies.

The shim obtains the logon SID with `TokenLogonSid`. Native tests compare it with the logon entry in `TokenGroups` in all three modes. Admission checks the count, returned size, SID bounds, required logon-ID attributes and restricting-SID membership. Bounded storage keeps the selected SID valid through copying and avoids heap allocation or fallback under loader lock.

### Child executable selection

The `CreateProcessW` hook redirects direct children of the source or runtime `usr/bin` into the view. The mandatory `etc` junction identifies the source root. The native `bin/bash.exe` wrapper remains distinct. An unrelated launch receives the original path. A failed rewrite reports the error without retrying the installed source. Input, long-name expansion and output overflow return `ERROR_FILENAME_EXCED_RANGE`.

Long-name lookup retains an extended-length prefix supplied by the caller. Root comparison strips the prefix from the result. Root resolution propagates Win32 open and close errors. Outside DLL attach, `InitOnceExecuteOnce` publishes either the complete roots or a terminal error. Both outcomes complete the callback. Returning FALSE would permit a retry. [Microsoft once-initialization contract](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-initonceexecuteonce)

## Cache construction and lifetime

Each generation owns its flat executable copies. Preparation runs with ordinary user permissions and the source and cache can reside on separate NTFS volumes. The copy preserves each executable alias. The measured 355 source files total 92,906,374 bytes, and the private MSYS patch plus shim bring a generation to about 88.62 MiB. Other Git resources remain junction-backed. All DSH instances must close throughout same-root Git upgrades because the linked resources can change at the source. [Pinned-session replacement experiment](analysis_report/refactor-design-validation/evidence/storage.md)

Both selectable Bash entries require ordinary source `etc` and `bin` directories and the native `bin/bash.exe` wrapper. Discovery, provisioning, warm admission and tests use this contract. The builder rechecks those directories before creating the private layout. The `etc` junction identifies the source for child redirection, and `bin` exposes the native wrappers. Perl, library and libexec resources are retained. Git’s temporary and device directories are omitted.

Junction admission reads the stored target, checks each directory component without following reparses and compares the target’s NTFS volume and file ID. This distinguishes ordinary directories whose names JavaScript lowercases identically. It also rejects an intermediate junction even if that junction currently reaches the expected tree.

Storage remains under the owned DSH-home cache, with its delete-on-close sibling writer lock. The owner marker and current selector both use `schemaVersion: 1`. Preparation and offline purge require the marker to identify `dsh-git-bash-on-win/runtime-cache` and match the canonical root path, NTFS volume and file ID. A missing marker or a mismatch rejects the directory before its contents are changed. Short generation/view paths and the 260-byte UTF-8 guard reject over-budget homes before copying. Source/cache/workspace overlap is rejected before grants or mutation.

### Copying the executable directory

The builder opens each source without following reparse points and uses a short-lived `FILE_SHARE_READ` handle. Before allocation it checks the size from that same handle using BigInt, with a limit of 64 MiB for a payload and smaller limits for metadata. The handle supplies kind, identity and size for one read. Freshness sampling opens a new handle. Reads check for short data, growth past EOF and conversion overflow.

A shared Node `wx` writer creates independent files with inherited cache permissions. It preserves a pre-existing name on collision and reports write, close and rollback errors together. A close error on unpublished payload rejects the attempt. Native hold, lock and claim close failures remain fatal. [Read-only copy controls](analysis_report/refactor-design-validation/evidence/storage.md#how-to-copy-a-read-only-executable)

One source and one destination directory pin cover the flat copy. Standalone metadata writes take their own pins around the same writer. MSYS is patched and written first, so an unsupported image fails before an ordinary payload is copied. The builder closes each file before yielding, checks cancellation between files and closes directory holds on exit. The cooperating-host cache model permits path-based creation and publication. A separate handle-relative destination writer would address deliberate parent conversion by another process running as the same user, outside that model.

### Freshness, admission and publication

The source freshness key combines Git and MSYS file stamps with the raw SHA-256 of optional `etc/package-versions.txt`, bounded to 256 KiB. The selector records the package digest as JSON null or 64 lowercase hexadecimal digits. A malformed selector in an owned cache triggers preparation. The builder rechecks the entire key before publication. This detects normal packaged upgrades without starting Git or enumerating the tree. **Save and rebuild** also repairs custom changes that preserve the key. Each `prepareRuntime()` attempt reads and hashes its own copy of the bundled shim. Ready commands reuse the admitted generation.

On a matching source key, warm admission checks both shells and both private DLLs before classifying the payload as stale. A missing shell or digest mismatch cannot hide an access, structural or close failure in another required file. Digest mismatches or missing ordinary Bash/sh/DLL payloads trigger rebuilding, including a changed bundled shim with unchanged patch ABI. Unexpected reparses, redirected/dangling junctions, wrong types and access/read/close failures remain errors. Failed automatic rebuilding never serves stale disk copies. Validate new files/junctions as they are created and hash patched bytes before writing, avoiding a second complete destination scan immediately before publication.

The writer holds the lock and a generation pin while DSH atomically replaces `current.json`. A successful rename commits the new selector even if cancellation or cleanup follows. Readers pin then reread the selector. Collectors claim a generation exclusively before traversal. The builder pre-creates the view directory, `v/`. Command admission reuses a view synchronously after validating its junction against the pinned runtime.

### Collection and disposal

Collection runs during builds and offline purge. With the writer lock held, a build scans unselected orphans once. After publication it attempts to collect only the superseded generation. Releasing a pin cleans its owned views and closes the hold. An active command or peer can still pin the old generation after publication, so another immediate collection pass would add work without ensuring reclamation. Superseded copies may persist until a later build or purge. There is no fixed generation quota or background collector.

Work and cleanup have separate promise sets. A rebuild may publish B while a command continues using A. New preparation drains cleanup and can proceed while that command runs. Disposal joins preparation and owned children, closes instance handles and attempts view cleanup.

Offline purge validates ownership, claims generations and unlinks reparses without following their targets. It removes the ownership marker after the payload, just before removing the empty root. Termination between those operations can leave an empty markerless directory, which subsequent admission refuses. A blocked or interrupted purge reports failure.

## Build, packaging and dependencies

Share a bounded PE header/section/import reader and fixed MSYS patcher. Preserve ordinal imports and repeated descriptors, and expose DLL characteristics and export-directory fields from that parse. Build-only code interprets shim exports and validates mitigations/imports. The patch retains existing section positions and supported symbol/debug tails, bounds its new section header by both raw data and SizeOfHeaders, updates initialized-data size and checksum, and keeps the IAT span read-only. Source admission is structural rather than a source-hash whitelist; tested versions are recorded separately.

The patcher accepts unbound MSYS imports. Both qualified Git images have zero descriptor timestamps and forwarder chains. Rejecting bound descriptors preserves the original IAT bytes and avoids implementing rebinding. The reader requires an eight-byte-aligned NT header after the DOS header, nonempty mapped sections and nonempty names. These checks keep the checksum field aligned, give each section a distinct address and reject invalid imports before publication. [Microsoft PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)

The canonical native source lives outside the generated `lib/` directory. One build script uses the reviewed zero-CRT flags and `/Brepro` in a private temporary directory and checks cleanup. Every build enforces PE invariants and the named-function allowlist. Keep allowed membership rather than exact import equality: removed imports need no manifest edit, additions need review. A DLL-only allowlist or API deny-list misses unsafe functions; a release hash cannot validate a new development candidate.

Development builds report their actual tool versions/hash and remain testable before hash approval. Release builds and prepack require recorded tools and the approved hash. Compare two isolated builds before updating pins, then qualify the final DLL and tarball. Clean lib before building to remove obsolete outputs, package the DLL without native source/build scripts, and require no install-time compiler. Two-tree comparison belongs in release qualification rather than recursive prepack checks. The build verifier reads DLL names from the manifest’s own entries. The isolated-build test supplies invalid ambient compiler options and search paths so that a build depending on them fails.

The five direct runtime dependencies are `@deepseek-ai/schemastery`, `@deepseek-ai/dsh-atomic-write`, `@deepseek-ai/dsh-error`, `@deepseek-ai/dsh-win32-process` and `koffi`. Host Cordis/ACL peer identities remain shared, and SID-helper imports stay outside the standalone purge graph. Resolve the bundled DLL with `../../lib/dsh-msys-compat.dll` relative to runtime-cache, valid for source tests and packaged output. Remove obsolete filesystem exports with their debugger/setup callers. Add the UI-primitives development pin and release-age exclusion; prune other exclusions only when the retained dependency graph no longer needs them.

## UI and verification boundaries

Use native SettingsForm, SettingsValueField, Modal and Toast with page-local state and one rebuild endpoint. Preserve Save and rebuild, revision conflicts, blank-path reset, unchanged-path rebuilding with read-only settings and the saved-path/rebuild-failure distinction. Rich errors use Modal children. Guard async updates on unmount and handle rejections; navigation leaves accepted backend work running, and a later click can show the existing busy response. Delete global overlay, feedback/progress transport and custom styling; keep src/locale/ unchanged.

### What the maintained tests cover

Cache and PE tests use a small, independently encoded PE32+ MSYS fixture. Include the five required named imports, valid terminated descriptors/thunks, header room and read-only IAT data; pass it through the real patcher without production exceptions. Malformed fixture cases assert the diagnostic for the intended invariant. The native test sets invalid UTF-16 through Win32 because Node replaces the surrogate before the OS receives it. Keep executable/native qualification on owned real Git in both layouts. Synthetic fixture size is an implementation detail, not a 1.5 KiB target.

Share observers in fixtures.ts. Keep exhaustive PEB/token/ACL negative controls and 100-fork stress in native-compat.test.ts; real-executor tests cover argv/env/policy/lifetime plus representative image/view/fork and four-caller IPC checks. Settlement tests count waits and recorded failures for both disposal orderings. Environment tests cover an explicit PATH deletion in each caller layer and require the two runtime directories to remain. Native Windows integration tests require installed DSH and assert the specific ownership, schema or sharing error for a refused operation. Reused-view tests allow junction validation while forbidding selector/freshness/DLL rereads. UI tests assert native form usability and rich dialog content instead of custom geometry or paragraph tags.

Keep browser testing in test:release. Preflight DSH, Git and the Chrome executable before builds or fixture setup, using CHROME_PATH or the existing Program Files default through a shared small resolver. Missing Chrome is an early error, not a skipped browser suite. UI-only testing preserves the DLL from a prior full build and checks its existence; PE verification stays in build/native/release checks. Native edits require a full build.

Shared preparation may outlive a timed-out caller, but that command must never spawn later. Optional aliases/gdb remain explicit host qualification, with WinGet logging opt-in and missing coverage marked UNVERIFIED. Preserve normal endpoint protection; do not change settings or recommend exclusions.

Both READMEs explain practical differences from native Linux Bash, accepted command limits, retained-generation storage, all-instances-closed Git upgrades and automatic next-use rebuilding. Manual rebuild is repair; complete removal clears only the plugin override, closes sharing hosts, purges once and uses official package operations while preserving shared Shell settings.

## Release qualification

The release gate checks the installed DSH version, Git layout and Chrome executable before creating a profile or rebuilding. It runs type checking, lint, a clean pinned build, the Windows and browser suites, and two ordinary pnpm packs from separate source trees. The trees share build tools. Each starts with stale generated files and a different invalid DLL. The release test compares the complete tarballs. The clean build must match the Git index for the shipped library.

Use the rc.5 Web bundle template for both test profiles. Electron uses this template when initializing Desktop. DSH's package manager installs the tarball with scripts disabled and automatic peer installation off. Each packed profile runs its configured Shell and adapter entries through the DSH Loader in a separate Windows Node process. The packed preset must inherit from the host’s `AgentPreset` class. Workspace and sibling write probes distinguish the three policies. Process exit releases the native modules before package removal. The standalone purge starts a fresh process with resolution confined to the installed profile. These checks also cover one-profile removal while another profile retains the published generation.

The benchmark uses the installed copy package and the recorded shipping revision on disposable Git trees. It records command time through positive DSH managed-range settlement for a builtin, a pipeline and Git. Direct full-access Bash supplies a baseline. Warm admission measures the first preparation in a fresh Node process and verifies that the persisted selector stays identical. Fresh preparation, ready-use cost and bytes retained across rebuilds are measured separately. The [release audit](analysis_report/copy-backend-verification/evidence/release.md#independent-release-audit) identifies the qualified archive. The [timing report](analysis_report/copy-backend-performance/evidence/packed-runtime.md) gives both distributions and all measured rounds.
