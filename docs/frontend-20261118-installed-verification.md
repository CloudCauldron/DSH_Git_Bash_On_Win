# Windows Git Bash 插件配置页实包验收

2026-11-18，Windows 11 x64 10.0.26200.9974，Git for Windows 2.56.0.windows.4，Node 26.12.1，pnpm 12.18.0，DSH 0.2.2-rc.2。构建、测试、安装与卸载均从 Windows 原生 Git Bash 发起。

## 发布检查

`pnpm test:release` 通过类型检查、lint、清理构建和 166 项测试，失败、跳过均为零。

- 安装测试通过 DSH 插件管理器将工作区的 `file:` 包安装到临时 profile。对照构建目录逐文件比较 `lib/` 与补丁内容，核对清单、两种语言的 JSON 公开入口、词条占位符及随包 README。用宿主 resolver 验证包根适配器、执行器继承关系和共享 Shell schema 字段身份。
- 实包词典 GET 返回打包的两份 `messages`。执行器在线时，读取词典期间配置补丁内容一致，Git 路径探测与重建调用均为零。显式 POST 触发同一个探测观测点。执行器卸载后 POST 返回 404，剩余适配器仍可提供词典，撤销其注入作用域后 GET 返回 404。
- 客户端测试从公开的 `./client` 脚本挂载组件，覆盖草稿、版本冲突、只读状态、重复激活与手动重试。拒绝写入后的回读不可用、或提交抛错时，下一次提交仍携带首次编辑的 revision。成功保存后重建失败会保留路径和后端原因。
- 源文件检查分别比较内容哈希、硬链接数和 ACL。此次实测发现 `icacls` 末行的成功计数会随控制台语言变化。逐项核对 8,944 个文件和目录后，差异仅在该汇总行。测试现保留所有对象的 ACL 记录，并继续要求 `icacls` 成功退出。

## CLI、隔离与恢复

- 同样安装插件的 Windows headless profile 在无 Web 服务时通过 Bash 工具输出 `CLI-REAL-BASH=5.3.15(2)-release`。对照用的原生 headless profile 通过 PowerShell 工具返回主版本 7。普通 Git Bash 仍解析到已安装 Git 的 `usr/bin/bash.exe`。
- Arch Linux / WSL2 的 DSH 同为 0.2.2-rc.2。在临时 Linux profile 声明该包后，宿主报告仅支持 win32 并跳过该包。与声明前相比，`--dump-config` 输出逐字节一致，仍使用原生 `bash-sandbox`，未创建插件缓存。
- headless 退出后，用已安装包的 `lib/purge-runtime-cache.js` 清理其 profile 缓存。包清单和配置补丁逐字节一致，源链接数恢复。下一次 CLI Bash 调用成功，并发布新的代。
- 完全卸载仅移除用户层的 `gitBashPath`。关闭相关实例、成功清除各自缓存并核对源文件后，再通过官方包操作移除插件。Web profile 保留 1800 ms 和 128 字节两项共享设置。发布测试另行覆盖占用时阻止卸载、清除中断后显式失败及重试、删除 junction 时保留目标。
- 并发与关闭行为由发布检查中的原生用例覆盖。需要人工响应的 UAC 交互沿用此前的人工验证结果。[后端验收记录](backend-20261117-phase6-verification.md)

## 对抗审计后的实包复验

回环 HTTP 对照中，旧客户端会跟随 302、307 和 308，并把落地页的 200 当作链接成功。修正后，三个场景都只发出原请求并报告失败。重新安装最终包后，在 Chromium 中对一次重建返回 307，确认跳转目标收到零请求，缓存尚未创建。手动重试后，原生执行器发布了新代。两次点击期间配置补丁逐字节一致，关闭宿主并清除缓存后，夹具源文件的链接数恢复。

最终随包 README 的 SHA-256 为 `0964abe9f6dfef0ec0a4410f0e949118a50721f7603cd65efeb6173114a6abe2`。浏览器中正文标题只出现一次，位于路径字段之前，五处仓库文档引用均为纯文字。

## 配置反馈的原生弹窗与 Toast

在 Windows 原生 Git Bash 中运行 `pnpm test:browser`。测试用本机 Chrome 和临时 DSH Web profile 安装当前包，默认使用 Chrome 的标准安装路径，也可通过 `CHROME_PATH` 指定浏览器。

- 保存指向不存在的 Bash 的路径，核对原生 Modal 的标题、原样显示的 HTTP 500 原因，以及弹窗位于宿主的页面顶层。关闭弹窗后输入框保留已保存的路径。再次点击只重试链接，弹窗可通过 Esc 关闭。
- 在第一个标签页保留草稿，在第二个标签页保存有效路径并实际建立硬链接。成功 Toast 位于浏览器文档顶层并自动消失。回到第一个标签页提交旧草稿，宿主显示保存冲突 Modal 和最近确认的路径，保留草稿，重建请求计数保持不变。
- 客户端单元测试另行覆盖保存抛错、拒绝后的回读不可用、弹窗随语言切换更新，以及加载、不可用和只读状态下的控件行为。
